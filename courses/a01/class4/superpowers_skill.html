How to Access Skills / 如何存取技能

Never read skill files manually with file tools — always use your platform's skill-loading mechanism so the skill is properly activated.絕不要使用讀取檔案工具手動閱讀 Skill 檔案 — 請務必使用您所用平台專屬的 Skill 載入工具/機制，以確保該技能被正確啟用與生效。
  • In Claude Code: Use the Skill tool. When you invoke a skill, its content is loaded and presented to you — follow it directly.
  • In Codex: Skills load natively. Follow the instructions presented when a skill activates.在 Codex 中：技能會原生載入。當技能啟動時，請遵循其展示的指示。
  • In Copilot CLI: Use the skill tool. Skills are auto-discovered from installed plugins.
  • In Gemini CLI: Skills activate via the activate_skill tool. Gemini loads skill metadata at session start and activates the full content on demand.
  • In other environments: Check your platform's documentation for how skills are loaded.在其他環境中：請參閱您所使用平台的官方文件以瞭解技能是如何載入的。

Using Skills

The Rule / 核心規則

Invoke relevant or requested skills BEFORE any response or action. Even a 1% chance a skill might apply means that you should invoke the skill to check. If an invoked skill turns out to be wrong for the situation, you don't need to use it.在進行任何回應或採取任何行動之前，請務必先啟用相關或被要求之技能 (Skills)。 哪怕只有 1% 的可能性適用，也意味著您必須調用該技能進行檢查！如果啟用後發現該技能不適用於當前情況，您後續便不需要使用它。

🔄 技能執行流轉圖 (Skill Execution Flow)

下列為 Markdown 原生定義之 Flowchart，在 HTML 中我們將其轉譯為直觀的時間軸管線：
1
User Message Received (新任務/提問)

AI 助理接收到使用者傳送的訊息，啟動分析流程。

2
Might any skill apply? (技能匹配檢測)

AI 進入流程思維：這件事是否有對應之 Skill？哪怕只有 1% 可能性，也必須先載入檢測！

3
Announce Skill Usage (主動宣告使用技能)

AI 主動對使用者宣告："Using [skill] to [purpose]"，表示已進入該技能的 SOP 約束中。

4
Has Checklist? (檢查清單載入)

若技能中包含 checklist 任務清單，則自動在 Agent 工作區中為每一項建立 TODO 任務，並逐一嚴格執行與驗證。

5
Respond / Action (最終回應與產出)

執行完畢並取得本輪驗證證據後，AI 才對使用者進行回應或合併代碼。

Red Flags / 紅線警示

These thoughts mean STOP—you're rationalizing:當您在思考過程中出現以下想法時，代表您正在「自我合理化」規避流程，請立即停止 (STOP) 並嚴格執行檢測：
ThoughtReality
"This is just a simple question"👉 中文導讀：「這只是一個簡單的問題」Questions are tasks. Check for skills.👉 中文導讀：任何提問都是任務。立即檢查是否有適用之技能。
"I need more context first"👉 中文導讀：「我需要先取得更多上下文脈絡」Skill check comes BEFORE clarifying questions.👉 中文導讀：啟用與檢查技能的優先級永遠高於提出澄清問題。
"Let me explore the codebase first"👉 中文導讀：「讓我們先探索程式庫」Skills tell you HOW to explore. Check first.👉 中文導讀：技能會指導您如何探索。請先檢查與啟用技能。
"I can check git/files quickly"👉 中文導讀：「我可以快速查看 git 或檔案」Files lack conversation context. Check for skills.👉 中文導讀：單純看檔案缺乏對話脈絡。請先檢查技能。
"Let me gather information first"👉 中文導讀：「讓我們先蒐集資料資訊」Skills tell you HOW to gather information.👉 中文導讀：技能規範了該如何收集資料。
"This doesn't need a formal skill"👉 中文導讀：「這不需要使用正式的技能流程」If a skill exists, use it.👉 中文導讀：只要存在對應之技能，就必須使用它。
"I remember this skill"👉 中文導讀：「我記得這個技能規範了」Skills evolve. Read current version.👉 中文導讀：技能是持續演進的。請閱讀最新版本。
"This doesn't count as a task"👉 中文導讀：「這不算是一項任務」Action = task. Check for skills.👉 中文導讀：任何行動皆視為任務。立即檢查技能。
"The skill is overkill"👉 中文導讀：「使用這個技能實在是大材小用」Simple things become complex. Use it.👉 中文導讀：看似簡單的事情往往會變複雜。請嚴格遵循。
"I'll just do this one thing first"👉 中文導讀：「我只先做這件小事」Check BEFORE doing anything.👉 中文導讀：在動手做任何事情之前，先進行技能檢查。
"This feels productive"👉 中文導讀：「這樣做感覺很有生產力」Undisciplined action wastes time. Skills prevent this.👉 中文導讀：缺乏工程紀律的行動是在浪費時間。使用技能能防止這種情況。
"I know what that means"👉 中文導讀：「我明白那是什麼意思」Knowing the concept ≠ using the skill. Invoke it.👉 中文導讀：知道概念不等於有落實執行該技能。請啟用它！

Skill Priority / 技能優先級

When multiple skills could apply, use this order:當多個技能同時適用時，請遵循以下優先順序： 1. Process skills first (brainstorming, systematic-debugging) - these determine HOW to approach the task1. 程序類技能優先 (Process skills first)（例如 brainstorming、systematic-debugging）— 這些決定了「如何切入與規劃」該任務。 2. Implementation skills second (frontend-design, mcp-builder) - these guide execution2. 實作類技能次之 (Implementation skills second)（例如 frontend-design、mcp-builder）— 這些用來指導具體執行。 "Let's build X" → brainstorming first, then implementation skills.範例：「我們來開發 X」➔ 先啟用 brainstorming 技能，再使用實作技能。 "Fix this bug" → systematic-debugging first, then domain-specific skills.範例：「修復這個錯誤」➔ 先啟用 systematic-debugging 技能，再使用領域特定技能。

Skill Types / 技能類型

Rigid (TDD, systematic-debugging): Follow exactly. Don't adapt away discipline.嚴格型 (Rigid)（例如 TDD、systematic-debugging）：必須完全一字不差地遵循，切勿自行變通而妥協了工程紀律。 Flexible (patterns): Adapt principles to context.彈性型 (Flexible)（例如 patterns 等模式）：根據實際專案脈絡彈性適應其核心原則。 The skill itself tells you which.具體類型會在各技能檔案中自行聲明。

User Instructions / 使用者指示

Instructions say WHAT, not HOW. "Add X" or "Fix Y" doesn't mean skip workflows.使用者的指示規範的是「做什麼 (WHAT)」，而非「如何做 (HOW)」。「添加 X」或「修復 Y」等直接要求，絕不代表可以規避或跳過已定義的工程工作流程。
